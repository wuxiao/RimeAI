北极星目标（2026-10-26 确立，PRD §3）：做到拼音能直接盲打的程度。本
文档把该目标拆成可度量维度，逐项对照当前实测证据给出差距与主路径；
它不是能力声明，任务状态只维护于 [TASKS.md](../TASKS.md)。

**传导与归因前提**：现行交互合同（2026-10-26 拍板维持）下，Space
提交 Rime 主候选；神经整句建议只写独立建议位，经 Tab/点击等显式
`selectSemanticCandidate` 路径采纳，不重写 `mainCandidates`。因此
LM-002/LM-005 的 decoder 精度投资在当前合同下不传导到 Rime 主候选
提交文本。这不等于「所有盲打路径结构上不可达」——Tab 显式路径、
Rime 侧改进（词典/schema/用户词典学习）仍然存在；混输建议等既有
窄路径不属于 neural_late 整句链路。

first-shot 按提交路径分解：**rime_main**＝Rime 主候选提交（Space、
数字、段选择等），**tab_ai**＝显式语义建议采纳，其余路径单列。
**same_text** 是 rime_main 的同文归因子集，不是显式 AI 采纳，也不是
正确率；不得与 rime_main/tab_ai 并列后重复计数。

## 1. 目标的可度量拆解

盲打 = 用户不看候选框连续输入拼音（含标点、中英混输、简拼与错音），
句尾一次确认整句上屏，发现错误以段回修低成本修正。拆成五个维度：

| 维度 | 定义 | 达标线（初值，待 KBD-009 建立的采集链路校准） |
| --- | --- | --- |
| F1 精度 | first-shot 句准确率（句尾一次确认即正确），按 rime_main / tab_ai / 其他分别报告；same_text 一致率与 AI 显式采纳准确率单列，不与整体 first-shot 混算 | ≥97%（未修正率是正确率的上偏代理，须抽样人工标注/后编辑归因校准） |
| F2 接管覆盖 | AI 整句链路覆盖的输入形态比例；形态清单＝①单段（≤30 字无标点）②多段跨标点 ③无空格中英混输 ④简拼/缩写 ⑤音近/漏音节 ⑥>30 字长句 | 六类形态逐项给出「覆盖/不覆盖/未测」判定，主流形态全覆盖（未测不得当作已覆盖） |
| F3 时序与采纳 | 分开两个指标：①建议就绪时延（句尾停顿→整句建议可确认）②显式采纳率（tab_ai 占互动结局比例，仅监控用，不设达标线、不随 F1 自动达标） | 就绪时延 ≤300ms（P50/P95，待基线实测后定稿） |
| F4 修正成本 | 发现错误后的回修成本：按键数与时间（P50/P95，含 ← 焦点回移＋⌫×N＋重打×N＋space 定稿的全链） | 基线建立前不设数值门槛；先度量后定标 |
| F5 数据飞轮 | 真实使用信号进入蒸馏闭环的独立口径：真实行数、unique pinyin 数、真实占比、与目标分布的匹配度 | 口径可持续支撑蒸馏门（不绑定 LM-002 生命周期；LM-002 收口后指标继续独立成立） |

语言画像个性化的归属：L1 短语库（建议位）与 L2 用户 LM（排序融合）
当前主要作用于建议位/排序，在现行合同下不传导到 rime_main 提交文本
（Rime 自身的用户词典学习作用于 Rime 主候选，是 rime_main 侧的既有
学习通道）。画像对 first-shot 的贡献当前无法在 rime_main 上度量，
不得暗示已改善 rime_main。

## 2. 逐维度差距

### 2.1 F1 精度：制品×数据集二维口径——1.5B×zhwiki 差 1.4pp；真实分布仅 decoder 基线/mix1 有测值

精度必须按「制品 × 数据集」两维读，单维数字会误导制品选择
（LM002 报告 §10.5 已证实）：

| 制品 | zhwiki 冻结集（974 test） | 35 行干净真实集（real-holdout-v3） |
| --- | --- | --- |
| Rime 词级串接 baseline | 0.7269 | **未测** |
| 0.5B base decoder（无 SFT） | 0.9220 | 0.8857 |
| 0.60 门 decoder（产品口径） | 0.7885 | 未测 |
| 0.5B SFT 对照臂 | 0.9415（p50 124ms） | 未测 |
| 1.5B SFT（同数据同超参） | 0.9559（p50 218ms） | **未测** |
| 0.5B-mix1（含教师数据） | 0.9343 | 0.8857（相对无 SFT decoder +0.0pp，§10.5：此前的增益系训练记忆） |

- 0.7269 是 Rime 首选串接在静态 zhwiki 上的代理参考，**不是实测
  用户行为**；Rime 在 real-holdout-v3 上没有本节可引用的测值。
- 0.8857 来自 LM002 §10.5 的**无 SFT decoder 基线**，不是 Rime
  baseline。按该 decoder 基线计算，距 97% 约 8.4pp；这不能解释为
  rime_main 的真实分布差距，且 35 行统计功效不足。
- zhwiki 口径下 1.5B SFT 离 97% 差 1.4pp——这是当前最接近达标线的
  制品×数据集组合，但不等于「最接近突破」：同族 SFT 在真实分布
  尚未证明收益（mix1 干净集 +0.0pp；纯新数据曾负迁移 0.7084），
  1.5B 真实分布值未测是收口前必须补的腿。
- 错误分解（`reports/kbd002-sft-2000-taxonomy.json`）：57 错 =
  `model_path_miss` 44 + `gate_fuzzy_mismatch` 7 + `index_recall_miss` 6；
  1.5B 已把 model_path_miss 压到 32——蒸馏路线在 zhwiki 口径有效。
- 评测集噪声：zhwiki 派生 gold 含繁体（盡責/縣市/中興），t2s 转换
  unavailable——冻结集精度可能被低估，但噪声也污染错误分类。
- 0.60 门下的建议分布（974 样本）：no_change 649 / suggestion 168 /
  below_threshold 157——decoder 净增益主要来自 168 个建议样本。
- 延迟基准写清：1.5B SFT p50 218ms / 0.5B SFT p50 124ms = **1.76**
  （相对 0.5B SFT 臂；对 0.5B 无 SFT 115ms 为 1.90），超 ×1.2 门。
- **传导边界**：即便 LM-002 把建议位精度做到 97%，在现行合同下也
  不改变 Rime 主候选提交文本；first-shot 的 rime_main 腿度量的是
  Rime 主候选质量。

主路径：LM-002 收口（1.5B 学生 + 教师造数长句分布修复 + 真实数据臂
+ 1.5B 真实分布实测），收口时一并拍延迟取舍；度量基础归 KBD-009。

### 2.2 F2 接管覆盖：按形态清单逐项判定（最强链路不覆盖盲打主场景）

`TECHNICAL_DESIGN §4.3.1` 冻结规则：**多段（跨标点）请求 v1 不走神经臂**。
按 §1 形态清单逐项判定：

| 形态 | 链路现状 | 判定 |
| --- | --- | --- |
| ① 单段 ≤30 字 | 标准全拼单段神经臂覆盖（0.92+ 链路，LM-001） | 覆盖 |
| ② 多段跨标点 | 神经臂不覆盖（§4.3.1 冻结），走同步 n-gram beam（0.789 链路）+ KBD-006/007 分段机制 | **不覆盖**——盲打主场景（拼音+标点交替的长整句）恰在此 |
| ③ 无空格中英混输 | 整句臂口径未建立；v3 键盘集只覆盖逐词场景；Rime 不可解析时混输建议进主候选属窄例外 | **未测** |
| ④ 简拼/缩写 | 同上，词级有 v3 集证据，整句臂未测 | **未测** |
| ⑤ 音近/漏音节 | 同上 | **未测** |
| ⑥ >30 字 | 神经臂 `MAX_CHARACTERS=30`（`rimeai_daemon/neural_sentence.py`），同步 beam 也有 30 字上限 | **不覆盖** |

- 神经臂展示门 `min_confidence=0.0`（§4.3.1 校准证据）——接管是无
  条件的，「何时敢让提交基准依赖神经建议」没有置信度抓手。
- ③④⑤ 的「未测」不是「已覆盖」：覆盖判定须由 KBD-009 盲打冻结集
  给出实测，不得用词级场景证据冒充。

主路径：LM-005（形态②⑥）；③④⑤ 的测量归 KBD-009 冻结集。

### 2.3 F3 时序与采纳：same_text 非 AI 采纳；tab_ai 与 same_text 均非 first-shot

decision_log 单事务只读快照（2026-10-26，
`.rimeai/reports/blind-typing-decision-log-20261026-r2.json`，sha256
`5f2186958d70f6f3a61f1dd2931a9f43897dee5b977cb6fbd1486b070503e64e`；
窗口 2026-10-22 ~ 10-26，总量 7856 行）。r2 只修正归因元数据，
全部聚合数据与原快照一致；下表数字出自同一快照：

| 链路 | 互动结局¹ | tab_ai 显式采纳² | same_text（rime_main 归因子集）³ | rejected（不同文） |
| --- | --- | --- | --- | --- |
| neural_late | 1045 | 48（4.6%） | 730 | 267 |
| local_sentence | 229 | 4（1.7%） | 7 | 218 |
| local_rank | 84 | 1（1.2%） | 4 | 79 |

¹ 互动结局 = adopted + adopted_via_main + rejected（用户对展示建议做了
选择）；expired 5392 / pending 6 / superseded 1100 未入互动口径。

² adopted = 显式语义建议采纳（Tab/点击及 acceptedViaSemanticCandidate
路由），是神经整句建议的显式 AI 采纳通道；显式采纳率不是 first-shot
正确率。

³ adopted_via_main = Rime 主候选路径（Space、数字、段主候选等）的
提交文本与展示建议逐字相同。**它是 rime_main 的同文归因子集，不是
显式 AI 采纳，也不是正确率**。neural_late 在 same_text+rejected 两类
非显式互动中的同文占比为 730/(730+267)=73.2%，度量的是「神经建议与
Rime 主候选的一致程度」，不是 AI 接受率、接管质量或 first-shot。

关键洞察（修正后）：

1. **建议位不传导**：neural_late 接管建议位后，Rime 主候选提交路径
   不受其改写；73.2% 同文占比说明建议与 Rime 主候选高度重合，但那是
   归因统计，不是 AI 对上屏文本的因果影响。LM-002/LM-005 的 decoder
   增益在当前合同下不传导到 rime_main。
2. **显式采纳很低但路径存在**：tab_ai 显式采纳 48/1045=4.6%，与
   local_sentence 1.7%、local_rank 1.2% 同量级——独立建议位 + 显式
   确认不是用户的自然句尾动作。这是行为事实，不是结构不可达。
3. 上屏后修正（撤销/重打）完全未采集——first-shot 真实值当前不可测
   （KBD-009）；用户未修正率是正确率的上偏代理，须抽样校准。

主路径：KBD-009（first-shot 提交路径口径 + 采集 + 校准）；建议就绪
时延单独立标；显式采纳率仅作监控。

### 2.4 F4 修正成本：基础设施已齐，指标缺失

段回修（←/→ 焦点、按焦点删、部分选词保留 KBD-008、分段重推
KBD-006、云按段接受 KBD-007）已全部落地——五个维度中唯一基础设施
达标项。缺口是度量：修正成本＝按键数与时间的 P50/P95（全链：← 焦点
回移＋⌫×N＋重打×N＋space 定稿）。基线建立前不设「≤N 次操作」数值
门槛（避免假精确）。归入 KBD-009。

### 2.5 F5 数据飞轮：真实信号占比 4.6%（独立口径）

`datasets/sft-constrained-v1.lock.json`（2026-10-25，usable=true）：

- 总量 4137 行（unique pinyin 4117）；真实用户信号 192 行（4.6%），
  95.4%（3945 行）是 teacher_synthesis 造数。
- D 臂首日负结果（LM002 报告 §10）：造数短句（2-5 词）与评测长句
  不同构，纯新数据 0.7084 负迁移；长句模式重造数（4-12 词）待做。
- **采纳计数必须分证据域**：当前 lock 内显式 adopted=2 行；§2.3 的
  decision_log 快照内显式 adopted=53 行（neural_late 48 +
  local_sentence 4 + local_rank 1），尚未全部进入该 lock。两者不能与
  旧快照的 32 条混用。真实用户基数 = 1（开发者本人），飞轮有引擎

- 独立口径（不绑定 LM-002 生命周期）：真实行数、真实 unique pinyin、

主路径：LM-002 剩余项（长句造数 + 真实数据臂）+ 持续真实使用积累。

### 2.6 评测口径：无盲打形态冻结集，度量链路缺失

- 现有 v3 键盘冻结集 = 逐词选择场景（20 场景 7 类）；974 句集 =
  静态 zhwiki 长句（test 集无跨标点形态）——都不是「连续无选词流 +
  first-shot + 修正成本」的盲打形态。
- first-shot 口径（用户未修正率）测量链路缺失：decision_log 只记
  上屏前；上屏后撤销/重打未采集。
- loop-gates model 门：2026-10-26 已实跑（见 §2.7）并完成时延归因
  （§2.8）——frozen 腿精度/时延均过地板；holdout 腿时延超的是
  frozen 派生共用地板，归因＝真实历史输入更长（长度主导）+ 机器负载
  系统性漂移，非制品回归；时延地板已按腿标定（见 §2.8）。

主路径：KBD-009（盲打冻结集 + first-shot 采集 + 评测去噪与证据
口径）；model 门按腿时延地板已落地（§2.8），整体 PASS 归档待
空闲机器窗口重跑。

### 2.8 holdout 时延归因与按腿地板（2026-10-26，已完成）

归因报告：`.rimeai/reports/holdout-latency-attribution-20261026.json`
（sha256 `ae2b5f7961ff2bf51c2d96c0f944a306b14d098acd1752f76a29064a5330986e`；
同轮 frozen 974 + holdout 48×2 采集，同 artifact 同服务，仅数值）。
结论：

1. **长度主导**：同轮内 holdout/frozen p50 比值 1.646（gate 轮 1.517）；
   解码子群时延随拼音长度单调上升（中位数 397ms@3-8 键 → 682ms@9-11
   → 805ms@12-14 → 1160ms@15+），真实历史拼音均值 9.1 vs 冻结集 6.4。
2. **组成效应**：48 个 holdout 样本中 19 个（40%）是 <100ms 早退空建议
   （探针验证：空建议、confidence 0.0），把 p50 拉低——慢子群 p50 实为
   791ms，比标题 p50 更重。空结果≠快：长拼音空结果仍需全 beam 探索。
3. **系统性漂移独立存在**：frozen 腿今天比自身 2026-10-13 基线（同
   artifact+同数据集）慢 +30~42%（采集时负载 ~237，并行 Xcode 构建），
   两腿同时被放大，非制品回归。
4. frozen 腿线性外推不可用（按 gold 长度拟合预测 2.88×，严重过度
   预测）——短输入域不能外推长输入域。

处置：`tools/run_loop_gates.py` 时延地板按腿标定
（`MODEL_HOLDOUT_P50_MS=555.158`×1.5=832.737ms 预算，与精度地板
0.90/0.78 按腿分档同一先例；校准源＝本次 gate 实测，负载条件已在
归因报告记录），新增 3 个单测（合计 42 passed）。整体 model 门
PASS 归档待空闲机器窗口重跑（当前负载下 frozen 腿仅余 5% 预算余量，
重跑会产出负载污染的归档）。

   （Space 翻转或首选注入，精度达标后再议）。
